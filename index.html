Module 1: The Boot Foundation

Solving the "Chicken and Egg" problem of computing.

The CPU Reset Vector

When power stabilizes, the CPU is dumb. It only knows one thing: Go to a specific address (Reset Vector) and execute what's there.

PC (Program Counter) = 0xFFFF0

The Bootloader

A small program whose only job is to:

  1. Initialize minimal hardware (DRAM).
  2. Find the OS Kernel.
  3. Load it into RAM.
  4. Jump to it.

Module 3: NVMe Boot Partitions (BP)

The NVMe Spec mechanism for simplified embedded booting.

The Complexity Problem

Standard NVMe Read commands require a complex full-stack setup:

  • ❌ Admin Queue: Requires ASQ/ACQ memory allocation.
  • ❌ Controller Enable: Must set `CC.EN=1` and wait for `CSTS.RDY`.
  • ❌ Doorbell Handling: Managing submission/completion pointers.

Too heavy for a 10KB on-chip BootROM!

The Spec Solution (NVMe 1.3+)

Boot Partitions allow data retrieval via simplified MMIO writes.

[Spec Definition]

CAP.BPS (Bit 45): 1 = Controller Supports Boot Partitions.

BPINFO (Offset 40h): Reports Size (BPSZ) & Active ID (ABPID).

BPRSEL (Offset 44h): The Trigger Register.

Module 4: Spec Compliance Testing

Validation Checklist for Embedded NVMe Integration.

Dom 1

Capability & Discovery

BP_01 & BP_02: Basic compliance checks.

◻BP_01: CAP.BPS (Bit 45) must be 1.
◻BP_02: BPINFO Defaults (Size > 0, ABPID Valid).
◻BP_03: BPINFO is RO, BPSEL is R/W.
Dom 2

Pre-Enable Boot ("PBL" Flow)

BP_05 - BP_09: Reading without Queues (`CC.EN=0`).

◻BP_05: Read BP0 (SBL) while Disabled.
◻BP_08: BRS Polling (01b -> 10b).
◻BP_09: DMA Interruption / Reset.
Dom 3

Active Partition (Redundancy)

BP_10 - BP_13: Managing A/B boot slots.

◻BP_10: Read ABPID (Current Active).
◻BP_11: Commit Action 7 (Swap Active).
◻BP_13: Persistence across Power Cycle.
Dom 4

Image Update (Admin Cmds)

BP_14 - BP_18: FW Download & Commit.

◻BP_14: FW Image Download (Cmd 01h).
◻BP_15: FW Commit Action 6 (Update Inactive).
◻BP_17: Partial Update / Size Mismatch.
Dom 5

TP 4170 Security (Locking)

BP_19 - BP_24: Write Protection.

◻BP_20: Set Feature 15h (Lock BP0).
◻BP_21: Write Rejection (Status 86h).
◻BP_23: Read while Locked (Must Succeed).
Dom 6

Negative / Boundary Tests

BP_25 - BP_32: Error Handling.

◻BP_25: Offset Overflow (> BPSZ).
◻BP_27: Invalid BPID (e.g. ID=2).
◻BP_32: Hot Reset Recovery.
TC-04

Performance KPI

Measure critical boot timing metrics.

TTFI (Time To First Instruction) < 50ms POR -> First valid Opcode fetch from SRAM.
